# Запуск проекта

## Что нужно

Только [Docker Desktop](https://www.docker.com/products/docker-desktop/). Python, PostgreSQL и всё остальное работает внутри контейнеров.

## Запуск одной командой

```bash
./run.sh start
```

Скрипт сам:
1. проверит, что Docker установлен, и запустит Docker Desktop, если он выключен (на macOS);
2. создаст `.env` из `.env.example`;
3. сгенерирует пароль тестовых аккаунтов и сохранит его в `.env`;
4. соберёт и запустит контейнеры, дождётся, пока API ответит.

При старте бэкенд создаёт таблицы (миграции Alembic) и, если база пустая, заполняет её тестовыми данными: товары, новости, факты и по одному аккаунту на роль.

| Что | Адрес |
|---|---|
| Сайт (упрощённый фронтенд) | http://localhost:5173 |
| API и интерактивная документация | http://localhost:8000/docs |
| Adminer (просмотр базы в браузере) | http://localhost:8080 — сервер `db`, логин, пароль и база из `.env` |

Сайт обращается к API по своему же адресу (`http://localhost:5173/api/...`), nginx передаёт эти запросы бэкенду. Поэтому, чтобы открыть сайт с другого устройства (туннель, проброс порта), достаточно открыть один порт — 5173.

Бэкапы делаются в админке (раздел «Бэкапы») и лежат в папке `backups/` в корне проекта (в git не попадают). Автобэкап там же: по умолчанию выключен.

## Все команды

`./run.sh` без аргументов или `./run.sh help` выводит этот же список.

| Команда | Что делает |
|---|---|
| `./run.sh start` | всё сразу: проверить, настроить, собрать, запустить в фоне |
| `./run.sh stop` | остановить (данные базы сохраняются) |
| `./run.sh restart` | перезапустить |
| `./run.sh status` | какие контейнеры запущены |
| `./run.sh logs [frontend\|db\|adminer]` | логи в реальном времени (по умолчанию бэкенд). Выход: Ctrl+C |
| `./run.sh test [аргументы pytest]` | автотесты. Если проект не запущен — запустит. Подробнее в [TESTS.md](TESTS.md) |
| `./run.sh rebuild` | пересобрать после изменения `requirements.txt` или `Dockerfile` |
| `./run.sh migration "описание"` | создать миграцию после изменения `models.py` |
| `./run.sh locales` | проверить, что переводы ru/en совпадают |
| `./run.sh db` | консоль PostgreSQL (psql) |
| `./run.sh shell` | терминал внутри контейнера бэкенда |
| `./run.sh setup` | только подготовка, без запуска |
| `./run.sh ide` | подготовить редактор кода: библиотеки Python в `backend/.venv` для подсказок и проверки |
| `./run.sh typecheck` | проверить типы в коде бэкенда |
| `./run.sh password` | показать пароль тестовых аккаунтов |
| `./run.sh reset` | стереть базу и создать заново (спросит подтверждение, `-y` — без вопроса) |
| `./run.sh demo` | наполнить базу демо-данными: ещё 61 товар с картинками, новости и события, 12 клиентов с заказами во всех статусах, сборки, ремонт, поставки. Выполняется один раз; начать заново — `./run.sh reset -y demo` |

Команды можно писать подряд, они выполнятся по очереди: `./run.sh rebuild test`. Команды `logs`, `test` и `migration` забирают все аргументы после себя, поэтому их ставят последними.

## Тестовые аккаунты

По одному на роль:

| Email | Роль | Что увидишь в админке |
|---|---|---|
| `admin@store.dev` | администратор | все разделы |
| `manager@store.dev` | менеджер | дашборд, заказы, товары, приёмка, новости и факты |
| `employee@store.dev` | сотрудник | заказы, товары, сборки клиентов, приёмка |
| `engineer@store.dev` | инженер | ремонт |
| `senior-engineer@store.dev` | старший инженер | дашборд, ремонт, техподдержка |
| `client@store.dev` | клиент | админки нет; в кабинете — заказы, ремонт, бонусы, сборки |

Если аккаунты для новых ролей появились в коде позже, чем создана база, бэкенд при запуске добавит недостающие сам (нужен `SEED_PASSWORD` в `.env`). Пароль у них общий и хранится только у вас в `.env` (в git этот файл не попадает):

```bash
./run.sh password
```

Пароль применяется при создании базы. Чтобы поменять его, впишите новый `SEED_PASSWORD` в `.env` и выполните `./run.sh reset`.

## Редактор кода (VS Code)

Бэкенд работает в Docker, поэтому на компьютере библиотек Python нет, и VS Code (Pylance) показывает ошибки вида «Import "fastapi" could not be resolved». Чтобы их не было:

```bash
./run.sh ide
```

Команда создаст `backend/.venv` (в git не попадает) и поставит туда те же библиотеки. Pylance найдёт их сам по настройкам из `pyrightconfig.json`. После этого перезапустите VS Code или выполните команду «Python: Restart Language Server».

`./run.sh typecheck` проверяет типы так же, как Pylance. Перед коммитом стоит убедиться, что там `0 errors`.

## Изменение таблиц базы

1. Поменять модели в `backend/app/models.py`.
2. `./run.sh migration "что изменили"`.
3. Проверить новый файл в `backend/alembic/versions/`.
4. `./run.sh restart` — миграция применится при старте.

Если забыть шаг 2, тест `test_migrations_match_models` упадёт.

## Настройки (`.env`)

| Переменная | Что это |
|---|---|
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | доступ к базе |
| `JWT_SECRET` | секрет для подписи токенов входа |
| `CORS_ORIGINS` | адреса фронтенда, которым можно обращаться к API |
| `SEED_PASSWORD` | пароль тестовых аккаунтов (`./run.sh` генерирует его сам) |

## Без скрипта

`run.sh` — обёртка над Docker Compose. Если удобнее напрямую: `docker compose up -d`, `docker compose down`, `docker compose logs -f backend`, `docker compose exec backend pytest`.
