# Запуск на своём сервере (VPS)

Пошагово: как арендовать сервер, поставить на него проект и открыть сайт всем по постоянной ссылке.
Займёт около получаса. Всё, что нужно сделать на самом сервере, — несколько команд.

## Как это устроено

На сервере проект запускается командой `./run.sh deploy` — это тот же Docker Compose, что и на компьютере,
но с файлом `docker-compose.prod.yml` сверху:

```
Интернет ──► Caddy (порты 80 и 443, HTTPS) ──► nginx ──► сайт, /api, картинки
                                                 └──► FastAPI ──► PostgreSQL
```

| | На компьютере (`./run.sh start`) | На сервере (`./run.sh deploy`) |
|---|---|---|
| Что открыто наружу | сайт 5173, API 8000, база 5432, Adminer 8080 | **только 80 и 443** (Caddy) |
| HTTPS | нет | **сам**, если указан домен |
| Пароли и ключи | из `.env.example` | **генерируются** длинные случайные |
| Сервер API | с `--reload` (перезапуск при правке кода) | без него |
| После сбоя или перезагрузки сервера | — | всё поднимается само |

После `./run.sh deploy` в `.env` записывается `RUN_MODE=server`, и **все** команды `./run.sh` (stop, logs, demo,
photos, password…) дальше работают в режиме сервера.

---

## 1. Арендовать сервер

Нужен **VPS** — виртуальный сервер у любого хостинга (Timeweb Cloud, Selectel, Beget, Aeza, Hetzner и т. п.).

| Что выбрать | Значение |
|---|---|
| Система | **Ubuntu 24.04** |
| Процессор и память | 1–2 ядра, **2 ГБ** памяти (на 1 ГБ тоже заведётся, но включите подкачку — шаг 9) |
| Диск | от 20 ГБ |
| Доступ | по **SSH-ключу** (см. шаг 2), не по паролю |

После создания хостинг покажет **IP-адрес** сервера, например `203.0.113.10`.

## 2. SSH-ключ и вход на сервер

На своём компьютере (если ключа ещё нет):

```bash
ssh-keygen -t ed25519
```

Публичный ключ (`~/.ssh/id_ed25519.pub`) вставьте в панели хостинга при создании сервера. Потом войдите:

```bash
ssh root@203.0.113.10
```

## 3. Подготовить сервер

Все команды ниже — **на сервере**.

Обновить систему:

```bash
apt update && apt upgrade -y
```

Файрвол: пустить только SSH, http и https:

```bash
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
```

Docker (официальный скрипт установки Docker):

```bash
curl -fsSL https://get.docker.com | sh
```

Проверить:

```bash
docker compose version
```

## 4. Скачать проект

```bash
git clone https://github.com/MishaelS/Technology-Store.git && cd Technology-Store
```

Нужная ветка (по умолчанию `main`; если свежая работа ещё в `develop`):

```bash
git switch develop
```

## 5. (Необязательно) Домен и HTTPS

Без домена сайт откроется по IP: `http://203.0.113.10`. С доменом — по `https://` с бесплатным сертификатом.

1. Купите домен (или поддомен) и в его настройках DNS сделайте **A-запись** на IP сервера.
2. Подождите, пока запись заработает (обычно минуты): `ping shop.example.ru` должен показать IP сервера.
3. Перед запуском впишите домен:
   ```bash
   cp .env.example .env && sed -i 's/^SITE_ADDRESS=.*/SITE_ADDRESS=shop.example.ru/' .env
   ```

Caddy сам получит и будет продлевать сертификат Let's Encrypt.

## 6. Запустить

```bash
./run.sh deploy
```

Команда сама:
- сгенерирует пароль базы, ключ входа `JWT_SECRET` и пароль тестовых аккаунтов;
- соберёт и запустит контейнеры в режиме сервера;
- дождётся, пока API ответит, и покажет адрес сайта.

Наполнить витрину (по желанию):

```bash
./run.sh demo photos
```

## 7. Проверить

- Откройте `http://<IP сервера>` (или `https://<домен>`) — должна открыться главная.
- Пароль тестовых аккаунтов: `./run.sh password`. Вход: `admin@store.dev`.
- Логи: `./run.sh logs` (API), `./run.sh logs caddy` (сертификаты, входящие запросы).

## 8. Обновить сайт после изменений в коде

```bash
git pull && ./run.sh deploy
```

Данные в базе и загруженные картинки при этом сохраняются. Перед большими обновлениями сделайте бэкап:
**Админка → Бэкапы → Сделать бэкап** (можно и скачать его себе).

## 9. Если что-то не так

| Проблема | Что сделать |
|---|---|
| Сайт не открывается | `./run.sh status` — все ли контейнеры запущены; `ufw status` — открыты ли 80 и 443 |
| Не выдаётся HTTPS | `./run.sh logs caddy`; проверьте, что A-запись домена указывает на этот сервер и порты 80/443 открыты |
| Мало памяти (сервер на 1 ГБ, сборка падает) | включить подкачку 2 ГБ — команды ниже |
| Нужно посмотреть базу | `./run.sh db` (консоль PostgreSQL) — Adminer на сервере специально не запускается |
| Начать с нуля | `./run.sh reset -y` — **удалит все данные** |

Подкачка на 2 ГБ:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## Безопасность

- Файл `.env` с паролями живёт только на сервере, в git он не попадает. Не публикуйте его.
- Пароль тестовых аккаунтов (в том числе администратора) — случайный; узнать его можно только на сервере (`./run.sh password`).
- Наружу открыты только 80 и 443; база, API и Adminer снаружи недоступны.
- Это учебный проект: не храните на нём настоящие персональные данные и не принимайте реальные заказы.
