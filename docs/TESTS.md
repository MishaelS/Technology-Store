# Автотесты

Автотесты проверяют бэкенд по частям: у каждой части кода свой файл тестов. Если тест упал, по его имени сразу видно, где проблема.

## Запуск

```bash
./run.sh test                          # все тесты
./run.sh test -q                       # коротко
./run.sh test tests/test_builder.py    # один файл
./run.sh test -k bonus                 # тесты, в имени которых есть «bonus»
./run.sh test -x                       # остановиться на первой ошибке
```

Если проект не запущен, скрипт запустит его сам. Всё после `test` передаётся в pytest.

Все тесты проходят примерно за 10 секунд.

## Как устроено

- Тесты работают с **отдельной базой** `store_test`. Перед каждым запуском она создаётся заново через миграции (так заодно проверяются и они) и заполняется тестовыми данными. Рабочая база не трогается.
- Каждый тест выполняется внутри транзакции, которая потом откатывается. Поэтому тесты не влияют друг на друга, и их можно запускать в любом порядке.
- Запросы к API идут через `TestClient`, без настоящего сервера.
- Общие заготовки лежат в [`backend/tests/conftest.py`](../backend/tests/conftest.py): `client`, `db`, `make_user(role)` (пользователь + токен), `product(name)`, `ids(names)`, а также готовые сборки `GOOD_BUILD` и `BAD_BUILD`.

## Что проверяет каждый файл

| Файл | Часть кода | Что проверяется |
|---|---|---|
| `test_compatibility.py` | `services/compatibility.py` | каждое правило конфигуратора, уровни ПК, подсчёт мощности и БП, тексты на двух языках. Без базы |
| `test_security_and_helpers.py` | `security.py`, `pagination.py`, `services/bonus.py` | пароли, токены (чужой, просроченный, испорченный), курсоры прокрутки, предел бонусов 30% и кешбэк 5% |
| `test_i18n.py` | `i18n.py`, `resources/locales` | одинаковые ключи в ru и en, все ключи из кода существуют, выбор языка, запасной язык |
| `test_auth.py` | `routers/auth.py`, `deps.py` | регистрация, вход, профиль, блокировка, ошибки на языке запроса |
| `test_permissions.py` | `permissions.py` | права каждой роли, `permissions` в ответе `/me`, новая роль действует сразу, кто видит чужие заказы и сборки |
| `test_catalog.py` | `routers/catalog.py` | бесконечная прокрутка (нет повторов и пропусков при любой сортировке, даже если товар добавили во время прокрутки), фильтры, поиск, новости, главная |
| `test_cart_orders.py` | `routers/cart.py`, `routers/orders.py`, `services/orders.py` | корзина, остатки на складе, заказ, бонусы, все разрешённые и запрещённые переходы статусов, возвраты при отмене |
| `test_builder.py` | `routers/builder.py` | проверка сборки через API, сохранение, приватность сборок |
| `test_admin.py` | `routers/admin.py` | доступ каждой роли к каждому разделу, статистика, товары, комментарии к сборкам, новости, факты, пользователи, ручные бонусы |
| `test_service_endpoints.py` | `main.py`, миграции | health, языки, CORS, совпадение миграций с моделями |
| `test_edge_cases.py` | всё API | плохие данные: поля из пробелов, неверные телефоны, неверные типы в specs, опасные ссылки (`javascript:`), формат ошибок 422 и 500, вход с несуществующим email |

## Нюансы, которые ловят тесты

- **Прокрутка без повторов.** Курсор строится по значениям сортировки, а не по номеру страницы. Если это сломать, `test_infinite_scroll_returns_everything_once` упадёт.
- **Бонусы.** Предел — 30% суммы *и* баланс, берётся меньшее. Кешбэк начисляется только при `done`. Отмена возвращает и товар, и бонусы.
- **Права.** Права проверяются на бэкенде. Инженер не видит чужие заказы, менеджер не видит чужие сборки.
- **Забытая миграция.** Поменяли `models.py`, но не создали миграцию — упадёт `test_migrations_match_models`.
- **Плохие данные.** Строка вместо числа в характеристиках товара раньше роняла конфигуратор с ошибкой 500. Теперь такой товар не сохраняется (`test_wrong_spec_types_are_rejected`).
- **Переводы.** Добавили текст в `ru.json`, но забыли в `en.json` (или наоборот) — упадёт `test_same_keys_and_placeholders_as_russian`.

## Как добавить тест

1. Найти файл для нужной части кода (таблица выше) или создать `tests/test_<часть>.py`.
2. Написать функцию `def test_<что_проверяем>(client, ...)`. Нужные заготовки из `conftest.py` подставятся сами по имени аргумента.
3. Запустить `./run.sh test tests/test_<часть>.py`.

Правило: новая функция или исправленная ошибка — новый тест.
